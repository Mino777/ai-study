# 🤖 AI 활용 테스트 대비 트랙

> **왜 이 트랙:** 2025~2026 기술면접이 "코드를 짤 수 있나" → **"AI를 잘 몰고·검증하고·선택을 방어하나"** 로 이동.
> **너의 우위(반드시 각인):** 넌 이걸 이미 시스템으로 만든 사람이다 — AI 하네스(**스킬 65·에이전트 17·훅 57·메모리 671**, 검증 게이트·서브에이전트 오케스트레이션·falsification-first 검증 / 2026-08-03 실측). 남들은 "AI 써봤어요", 넌 **"AI 실패모드를 코드 게이트로 막는 인프라를 설계·운영했어요."** 이 트랙의 목표는 그 경험을 면접 언어로 번역하는 것.

## 🚨 iOS 현실 체크 (2026-07 리서치 교정 — 반드시 먼저 읽기)

> **AI-assisted 전용 코딩 라운드(Meta형 3-panel)는 아직 iOS 직군 표준이 아니다.** 롤아웃이 **backend / frontend / ML 먼저** 진행 중 (Meta는 "back-end·ops 롤 우선"). iOS 후보에게 AI는 주로 이렇게 나온다:

```
   iOS에서 AI가 나오는 실제 형태 (우선순위)
   ┌─────────────────────────────────────────────┐
   │ 1️⃣ 🗣️ 딥다이브/행동에서 "AI 어떻게 쓰나" 설명 │ ← 주력
   │    (Klaviyo 등 "AI fluency"에 프리미엄)        │
   │ 2️⃣ 📝 take-home에서 "AI 써도 됨, 선택 물어봄" │ ← 자주
   │ 3️⃣ 🖥️ 전용 3-panel 라운드                    │ ← Meta/Google 타겟 시만 (보험)
   └─────────────────────────────────────────────┘
```

**→ 초점 조정:** "CoderPad 3-panel 그라인딩"에 시간 쏟지 말고, **"AI 숙련도를 면접에서 말로 증명(fluency narrative) + 판단력"** 에 집중. 아래 4대 역량 중 특히 **3(선택 방어)·4(서사화)** 가 iOS에 직결. Meta형 모의(1️⃣)는 그 회사 지원 확정 시에만.

### 🖥️ Meta형 라운드 해부 (가장 흔한 실전 포맷)
```
┌─────────────┬──────────────────┬──────────────┐
│ 파일 탐색기  │   코드 에디터     │  AI 챗 패널   │
│ (멀티파일   │   (네가 편집)     │ (AI는 답만·  │
│  코드베이스) │                  │  파일편집 X) │
└─────────────┴──────────────────┴──────────────┘
    60분 · 3단계 진행:
    ① 🐛 버그픽스  →  ② 🔨 코어 구현  →  ③ ⚡ 최적화
```
**핵심:** AI는 챗으로 조언만 하고 **파일을 직접 못 고침** → 네가 **판단·통합·검증**의 주체. "AI가 대신 풀어주는 시험"이 절대 아니라 **"AI를 도구로 쓰는 너의 판단력"** 시험.

### 📊 Meta 4대 평가기준 (이걸로 채점당함)
```
① 문제해결(Problem Solving)   요구사항 분해·접근 설계
② 코드품질(Code Quality)      AI 출력을 프로덕션 수준으로 정제
③ 검증(Verification)          ⭐ AI 코드의 버그·엣지·잘못된 가정을 잡아냄  ← AI시대 핵심
④ 커뮤니케이션(Communication) 생각·의도를 계속 소리내기 (관찰자에게 들려줘야 채점됨)
```

### 🔁 실제 진행 3단계 (평가 관점)
```
1단계  문제 분해     ⛔ 아직 AI 안 씀. 순수 분석력 관찰 (요구사항 쪼개기)
2단계  AI로 구현     프롬프팅·반복 품질·통합력 관찰
3단계  리뷰 & 정제    AI 출력 검토 + 테스트 추가 + 결정 방어
```
> 과제 자체는 [🐛 버그픽스 → 🔨 구현 → ⚡ 최적화]로 흐르고, 그 위에서 위 4기준·3단계 행동이 평가됨.

## 🎯 4대 역량 (드릴 대상)

### 1. 🎯 프롬프팅 / 컨텍스트 설계
- 멀티파일 코드베이스에서 **관련 맥락만 골라 AI에 주입** (전체 덤프 X)
- 큰 작업을 **검증가능한 작은 단위로 분해**해서 요청
- 하네스 연결: 네 JIT 검색(전체 331K→800토큰)·서브에이전트 태스크 분해가 곧 이 역량
- 🏋️ 드릴: 낯선 오픈소스 파일 1개 → "이 버그 고쳐줘"를 **맥락 3줄 + 제약 명시**로 프롬프팅. 나쁜 프롬프트 vs 좋은 프롬프트 대조.

### 2. 🔍 검증 · 회의(skepticism) — **가장 중요**
- AI 출력을 **믿지 말고 반증우선으로 읽기** (환각·엣지케이스·미묘한 버그)
- "이거 왜 맞다고 확신해?"에 답할 근거 확보
- 하네스 연결: `verifier-falsification-first`(agreement bias 회피, failure detection +25%p), 검증 게이트, 3-오라클 대조
- 🏋️ 드릴: AI가 짠 코드에 **일부러 심어둔 버그**를 제한시간 내 찾기. "그럴듯하지만 틀린" 답 감별 연습.

### 3. ⚖️ 툴 / 접근 선택 방어
- "왜 이 라이브러리? 왜 이 구조? AI 제안을 **왜 거절/수용**?"
- AI가 준 3가지 옵션에서 **트레이드오프로 하나 고르고 방어**
- 🏋️ 드릴: AI에 "3가지 방법 줘" → 각각 트레이드오프 표 만들고 **하나 선택 + 이유**. 아키텍처 4틀 재활용.

### 4. 🗣️ 의사결정 서사화 (take-home 방어)
- 과제 후 "왜 그렇게 했나" 방어: [상황→결정→트레이드오프→**mitigation**] 4틀
- "AI가 제안했지만 **내가 이래서 바꿨다**"가 시니어 신호
- 🏋️ 드릴: 작은 기능을 AI로 구현 → **결정 로그**(무엇을 AI에 맡기고/거절/검증했는지) 작성 → 5분 구두 방어.

## ❌ 떨어지는 5대 실수 (리서치 실측 — 이것만 피해도 상위권)

> 실제로 대부분의 후보가 AI-assisted 라운드를 **틀린 멘탈모델**로 접근해 떨어진다.

```
1. 🧠 문제 이해 전에 프롬프트   "가장 큰 단일 실수." AI를 답 기계로 취급.
                               → 먼저 요구사항 분해(1단계 무AI)부터.
2. 📋 읽지 않고 붙여넣기         AI 출력 이해 없이 수용 → "이 함수 뭐하죠?"에 버벅.
                               → 코드 품질 판단 불능 = AI시대 최악 신호(치명타).
3. 🌀 프롬프트 죽음의 소용돌이   에러 뜨면 AI에 계속 되물음. 3~4턴 후 자기 코드도
                               설명 못 함 → "그건 AI의 면접이지 네 면접이 아님."
4. 🔍 검증 부실                 AI는 데이터모델 오가정·엣지 누락·"맞아 보이는데
                               미묘히 틀린" 코드 생성. 안 걸러내면 감점.
5. 😱 도구 실패 시 패닉          AI에 전부 의존 → 툴 먹통되면 무너짐(의존도 노출).
```

## ✅ 좋은 접근 vs 나쁜 접근 (멘탈모델)

```
        나쁨 ❌                          좋음 ✅
   "자동완성으로 빨리 코딩"           "AI는 조수, 운전자는 나"
   AI가 solution을 driving            내가 항상 solution을 lead
   조용히 붙여넣기                     붙여넣는 이유까지 오버커뮤니케이션
   "AI가 맞겠지"                       "이 부분 의심스러워서 검증했다"
```

> 🗝️ **황금률 3개:**
> 1. **AI는 assistant, not driver** — 항상 네가 방향 잡고 AI는 실행 보조.
> 2. **오버커뮤니케이션** — "지금 이걸 왜 AI에 물어보는지 / 왜 이 답을 채택·거절하는지" 계속 소리내. 관찰자는 네 사고과정을 들어야 채점함.
> 3. **믿기 전에 의심** — 붙여넣기 전에 "이거 왜 맞다고 보나"를 스스로 답할 수 있어야.

## 🗣️ 행동면접: "AI 어떻게 쓰세요?" (iOS 직결 — 주력 경로)

> iOS는 전용 라운드보다 **행동/딥다이브에서 AI 사용을 *말로* 검증**하는 경우가 많음(AI 이후 소프트스킬·판단력 배점↑). "AI로 알고리즘은 풀리니, 못 대체하는 건 트레이드오프 설명·모호함 항해·압박 속 소통."

**STAR로 답하기** ("AI를 실제로 어떻게 썼나"):
```
S 상황   어떤 작업/제약에서
T 과제   무엇을 해결해야 했고
A 행동   AI에 무엇을 맡기고 / 무엇을 직접 판단·거절·검증했는지 (선택의 이유)
R 결과   지표·임팩트 + 배운 것
```
- ⚖️ **핵심 = 정직 + 판단.** "다 AI로 했어요"(❌) / "AI가 X 제안했지만 Y 이유로 제가 바꿨습니다"(✅ 시니어 신호).
- 🗡️ **너의 필살기:** 대부분은 "Cursor 써봤어요" 수준. 넌 하네스로 **AI 실패모드를 코드 게이트로 막은** 사람 → 아래 매핑표가 곧 STAR 스토리 재료.

## 🗡️ 너의 하네스 → 면접 스토리 매핑

> 이미 만든 걸 면접 언어로. 각 항목 = "AI 협업 STAR 스토리" 후보.

| 하네스 자산 | 면접에서 증명하는 역량 |
|------------|----------------------|
| verifier-falsification-first | "AI 출력을 맹신 안 하고 검증 프로토콜을 설계" |
| 검증 게이트(gate-1·ship-radar·preflight) | "AI가 저지르는 회귀를 코드 게이트로 left-shift" |
| 서브에이전트 오케스트레이션 | "큰 작업을 병렬 검증가능 단위로 분해" |
| 박제 메모리(auto-PR 지식그래프) | "AI 협업 지식을 팀 자산으로 복리 축적" |
| JIT 검색(331K → ~800 토큰, 내 자체 집계) | "컨텍스트를 효율적으로 주입하는 설계" |
| 지표 재측정 스크립트(`measure-harness-stats.sh`) | "내 주장의 근거가 늙지 않게 자동화 — 측정 가능성 자체를 설계" |

**엘리베이터 피치(연습):** *"저는 AI를 '빠른 코드 생성기'가 아니라 '검증 가능한 협업자'로 다룹니다. PR 리뷰 게이트도 없는 실상용 앱에 에이전트를 태우면서, AI가 저지르는 실패를 박제·측정·차단하는 자기개선형 하네스를 **약 4개월** 운영했습니다. 그래서 저는 AI를 언제 믿고 언제 의심해야 하는지를 코드 레벨로 압니다."*

> ⚠️ **숫자 규율 (2026-08-03 감사에서 발견):** 이 문서와 `interview-stories/07` 부록의 숫자가 **최대 +320(커밋)까지 늙어 있었다**(스킬 59→65, 메모리 579→671, 훅 46→57). 면접에서 "스킬 59개"라고 말했는데 실제가 65개면 신뢰를 잃는다.
> ```
> 면접 전날 재측정:  HARNESS_DIR=… APP_DIR=… bash scripts/measure-harness-stats.sh
> 말할 때는 항상:    "제가 마지막에 측정했을 때 기준으로 …"
> ```
> ⛔ **출처를 섞지 마라.** `falsification-first 검증 정확도 +25%p`는 **내 실측이 아니라 논문 수치**(arXiv 2507.11662)다. "제가 측정했습니다"라고 말하면 날조가 된다. → *"그건 설계 근거로 삼은 논문 수치이고, 제가 그 실험을 돌린 건 아닙니다."* ← 이렇게 말하는 게 오히려 신뢰 신호. 전체 출처 구분표는 `interview-stories/07` 부록 참조.

## 🏋️ 연습 프로토콜 (혼자 하는 드릴 — 회사 환경 OK)

> "문제 더 풀기"가 아니라 **설명·검증·프롬프트 규율·실패모드**를 연습. 실제 네 워크플로(Cursor/Claude Code)에서.

1. **🔍 버그 감별 드릴:** AI에 코드 생성시킨 뒤, 붙여넣기 전에 **"여기 버그/엣지/잘못된 가정 있나?"를 먼저 손으로** 찾고 → 그다음 검증. (2단계→3단계 근육)
2. **🗣️ 오버커뮤니케이션 드릴:** 작업하며 **소리내 녹음** — "왜 이걸 AI에 묻나 / 왜 이 답 채택·거절하나". 다시 들어보면 침묵 구간이 감점 포인트.
3. **🧠 무-AI 분해 드릴:** 요구사항 받으면 **AI 켜기 전 5분** 손으로 분해(1단계). 프롬프트 조급증 교정.
4. **🎤 STAR 스토리 드릴:** 하네스 자산 1개 골라 2분 구술 STAR. "AI가 X 제안 → Y 이유로 내가 바꿈" 패턴 연습.
5. **😱 툴 실패 대비:** AI 없이도 접근 설명 가능한지 점검(의존도 낮추기).
