> - **개념 1개 = 3층으로 답한다:** ① **도메인 원리**(왜 위험한가) → ② **Swift 구현**(`actor`/`Task`/`AsyncSequence`/`Sendable`/`@Observable`/`Combine`/`RxSwift`/`URLSession`/`CoreLocation`/`CoreBluetooth`/`Keychain` 등 실제 타입·API 이름) → ③ **iOS 함정**(스레드·retain cycle·백그라운드 정책·앱 생명주기·메모리·배터리·심사)
> - **모범 예:** 「멱등키」→ 원리(같은키+다른페이로드=409) + Swift(`actor IdempotencyStore` + 재시도 루프 **밖**에서 키 생성 + `Keychain`/파일 영속화 + `URLSession` 재시도와 `Task` 취소 상호작용) + 함정(앱 킬 시 `Task` 소멸 → 키가 메모리에만 있으면 유실 → 조회 불가)
> - **인출 질문도 착지시킨다:** T1/T2 문항에 *"어떤 Swift 타입/API로?"* 를 1줄 덧붙인다. 답변 채점 시 도메인만 맞고 구현이 비면 **부분정답**으로 처리한다.
> - ⛔ 회사 코드 식별자는 여전히 금지(`no-company-names.sh` 가드) — **표준 Apple API 이름과 일반 패턴만** 쓴다.
